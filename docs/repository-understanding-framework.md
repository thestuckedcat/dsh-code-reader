# 陌生仓库理解框架：分析角度、阅读顺序与六视图映射

编号：**CL-READ-01**；修订：2026-11-23。状态：用户已要求交付的分析与设计；本文中的目标交互不表示已经实现。当前实现逐项见[差距分析](repository-understanding-gap-analysis.md)。

**2026-11-24 用户纠正 / CL-READ-OUTLINE-01：** 默认目标是从现有代码提取“从零搭建这段业务时会列出的骨架”，帮助读者抓住业务目标、主要阶段、核心对象和模块分工，并快速进入源码。十四角度用于后台检查遗漏，不把它们变成首屏的概念与文字负担。主图只留少量业务阶段及精炼文字，点击阶段再给关键函数；校验、加锁、重试和清理默认按需展开。会改变业务结果、路由或状态模型的判断仍属于主线，不能一律归为防护。这里还原的是有源码依据的职责与设计框架，作者历史动机仍是推断。

## 1. 目标与适用边界

读者懂编程，但不了解仓库业务。目标是让他能说明：这个系统为谁做什么、代码如何分工、一个请求怎样推进、关键数据和共享状态怎样变化，以及当前函数处于什么位置。无需完整读完仓库才开始理解。

本框架以源码理解为主。构建目标、编译宏、生成头和测试仅在影响源码解释或提供行为证据时展开，不扩展成部署运维手册。适用于不同仓库；当前插件以 C/C++ 为主，其他语言和跨语言关系按实际能力单列。驱动、库、服务不套用同一业务结构：纯库可以没有守护线程，用户态服务不默认有设备寄存器。

**分析角度是检查理解是否遗漏的清单，阅读层次是控制信息展开顺序的路线，两者不能混为固定的调用深度。** 各角度按当前问题适用性选择：不适用说明原因；没有证据标未知；不要求一次全部分析。

本文沿用 [CW-01..11](interactive-code-view-software-design.md#2-用户约束与验收映射)、[CL-RES-01](interactive-code-view-software-design.md#11-资源变更链与共享状态关注cl-res-01) 和 [CL-GEN-01](interactive-code-view-software-design.md#12-跨仓库通用性约束cl-gen-01)。既有[四层函数阅读策略](../skills/learn-code-workspace/references/layered-reading.md)继续用于短问答；下面的五层路线用于整个仓库，不替换其合同。

## 2. 由浅入深的阅读路线

| 层次 | 先回答什么 | 最小产物 | 何时停止继续展开 |
|---|---|---|---|
| L1 整体认识 | 谁因为什么发起操作？操作的业务结果是什么？核心名词指什么？ | 一句话业务主线、核心术语与对象、完成/失败的定义 | 已能定位当前问题；无证据的业务动机保留推断 |
| L2 代码骨架 | 有哪些模块、运行主体和外部边界？初始化与接口分布在哪里？ | 模块职责地图、`文件 → 主要函数 → 职责 → 关键对象` | 找到当前流程涉及的模块和入口，不逐文件翻译 |
| L3 一条主线 | 请求怎样进入、判断、转换数据、交接并返回或完成？ | 一个入口的主流程、关键分支、生产者到消费者的数据流 | 主线及改变结果的分支已清楚；旁支列出后按需查 |
| L4 状态与耦合 | 不同入口共享什么？实例、状态、锁、异步、失败清理怎样关联？ | 接口—资源关系、资源变更链、必要的上下文/完成关系 | 当前问题依赖的状态和保护范围已解释；未知不补齐 |
| L5 具体实现与证据 | 关键条件、结构、封装怎样实现？结论在哪种源码/构建条件下成立？ | 定位到调用点、字段、定义和源码的解释，附覆盖缺口 | 可以用源码解释关键因果；稳定组件只保留相关契约 |

主线模板：**触发与输入 → 关键决策/数据或状态变化 → 交给谁 → 何时完成或失败**。每步说明它依赖什么、为下一步建立什么条件；初始化、失败清理和异步完成是主线的关联分支。

问单个函数时，先用一句话定位业务作用，压缩 L1/L2，展开相关的 L3/L4，按需进入 L5。可以从入口、资源、异常或任意函数开始阅读，再补回整体位置，不强迫用户从仓库首页走完全部步骤。

## 3. 十四个分析角度

下表的“来源”是查证方向，不是可信度承诺。README/注释用于找概念候选；当前源码、构建事实和观测分别支持不同结论。文档与实现冲突时保留差异。

| ID / 角度 | 核心问题 | 优先查证来源 | 最小解释与停止条件 |
|---|---|---|---|
| READ-01 业务目标与术语 | 谁要什么结果？核心对象、操作和完成分别是什么意思？ | 公共接口、数据模型、代表流程；README/设计文档作线索 | 一句话主线、少量必要术语；不推演无证据的产品目标 |
| READ-02 系统边界与运行主体 | 哪些程序、进程、线程、设备或远端参与？控制权在哪里交接？ | 构建目标、入口、线程/任务创建、服务声明、通信接口 | 当前流程相关的主体与边界；未确认域为 unknown |
| READ-03 模块、文件与职责 | 谁承担流程的哪一步？目录组织与业务分工是否一致？ | 编译目标、符号、引用、文件实现 | 按流程列关键文件与函数职责；不把目录名直接当业务结论 |
| READ-04 接口与契约 | 输入/输出、副作用、校验、所有权、返回含义是什么？ | 声明、类型、guard、调用者、实现与错误枚举 | 可说明如何调用及影响什么；复杂基础接口可停在黑盒契约 |
| READ-05 生命周期与注册 | 如何创建、初始化、注册、就绪、注销和销毁？谁读取注册状态并分派？ | 初始化/清理、静态表、注册点、分派点、回调绑定 | 把定义、注册、分派、触发分开；缺绑定处停止确定连线 |
| READ-06 控制流与分支 | 哪些条件改变执行、路由或结果？何处汇合、循环或返回？ | 调用点、CFG、guard、源码条件/返回 | 关键分支和路径条件；词法顺序不冒充完整 CFG |
| READ-07 数据流与转换 | 数据谁生产、复制、编码、传递、持有和消费？ | 参数/返回、赋值、别名、序列化、缓冲区及协议定义 | 关键值/对象的来源与去向；不能追踪的转换标断点 |
| READ-08 资源、身份与所有权 | 共享哪类资源、哪个实例/字段？谁创建、拥有、访问和释放？ | 声明、对象创建、容器、索引键、访问及生命周期调用 | 区分类型、实例、字段、所有者；不凭同名合并对象 |
| READ-09 状态与不变量 | 哪些状态允许转移？哪些条件必须成立？ | 枚举、字段写点、检查、状态转换与断言 | 有证据的前置状态、更新和约束；缺全路径时不补完整状态机 |
| READ-10 并发与异步 | 谁在什么上下文执行？锁保护哪次访问？投递和最终完成怎样关联？ | 线程/IRQ/任务、同步原语、RAII、回调、关联键、轨迹 | 按调用点/路径解释锁和交接；静态可能关系不当观测因果 |
| READ-11 异常、清理与补偿 | 何处失败？留下什么资源状态？谁撤销、重试、通知或恢复？ | 返回路径、goto cleanup、析构、补偿函数、超时处理 | 关键失败点到清理/未解决边界；不把返回成功等同业务完成 |
| READ-12 基础组件与外部依赖 | 哪些实现可以折叠？折叠后必须保留什么效果？ | 稳定职责、输入输出、封装实现、外部 ABI/库 | 契约、相关副作用、失败和实现简介；影响关注资源时继续展开 |
| READ-13 实现机制与设计取舍 | 当前结构、算法或封装解决什么问题？有什么代价？ | 实现、注释、调用者、测试和可用设计记录 | 解释当前关键机制；设计动机未经记录时标推断 |
| READ-14 证据、变体与未知 | 结论来自哪里？哪些宏/目标/版本改变它？覆盖到哪里？ | 源码身份、构建配置、语义图、证据引用、轨迹与覆盖报告 | 每个关键结论可定位，明确候选、截断、失效和未知 |

## 4. 六视图的职责与资源图合同

### 4.1 六视图各自回答的问题

| 视图 | 核心问题 | 细节展开方式 |
|---|---|---|
| 资源关系图 | 哪些入口通过哪些共享资源耦合，分别做了什么？ | 点击资源看定义；点击关系看实际访问点、路径、条件与证据 |
| 可折叠文字树 | 单入口的分支、调用、数据和清理怎样逐步展开？ | 按调用点展开；递归/重复实现用引用，保留当前上下文 |
| 端到端流程图 | 选定入口如何从触发走到各类结果？ | 竖向正交实线、标准形状、条件在线上、异常边；组可折叠 |
| 时序图 | 多接口按用户指定顺序或已有观测如何交互、交接与完成？ | 按有证据的参与者建生命线，区分静态场景与 observed |
| 文件视图 | 定义和具体实现在哪里？ | 文件树、只读源码、行号和语法高亮，定位对应符号/调用点 |
| 资源变更链 | 关注资源怎样沿相关路径被访问和改变？ | 多选资源；访问效果为前景、普通过程灰淡；保留调用点和锁上下文 |

仓库总览是六视图共用的背景说明和导航，不为十四个角度各加一个标签页。详细分支主要由文字树和端到端图承担，资源图只保留相关摘要、条件和跳转。

### 4.2 资源关系图的节点、线与详情

布局保持 **左侧函数—中间资源—右侧函数**。同一函数或资源在当前图中只有一个节点；同时读写的函数也不复制节点，用多条线/动作表达。默认主要写入者放左侧、只读者放右侧；位置不代表时间顺序。聚合/折叠只是展示方式，不改变实体身份。

| 元素 | 展示内容 | 点击后看到什么 |
|---|---|---|
| 函数节点 | 名称、简短职责、模块及已确认的执行域 | 选中函数并高亮关联资源；按既有详情交互查看契约、归纳、实现与资源分析 |
| 资源节点 | 名称、类型、用途、实例范围；独立颜色 | 定义/结构/字段解释、初始化值、访问与生命周期函数、来源及未知；无可用定义时显示原因 |
| 操作线 | 读、写、读改写、初始化、去初始化、分配、释放、加锁、解锁 | 实际访问函数、访问点、直接或入口投影关系、条件、路径候选、锁上下文与证据 |
| 线注释 | 字段、符号化实例键、动作和证据等级；已解析时加赋值/状态变化 | 长表达式在详情完整显示；不能解析的字段/键/值明确未知 |
| 注册/绑定关系 | 表中的键、值/回调，注册点及分派读取点 | 查看绑定证据，跳到注册和分派源码；注册不等于已经触发 |

读线从资源指向函数；写/初始化/释放等效果线从函数指向资源。读改写用相反方向的读、写效果或带两端箭头的专用线，必须附文字图例。获取/释放锁分别标动作，不从画面方向推断所有权。颜色区分关系，资源底色区分资源，两套颜色不得混用；文字和箭头保证无需仅靠颜色判断。

直接访问与入口汇总分开解释：`入口 A → 内部访问点 B → 资源 R`可以压缩成 A—R，但关系详情保留 B、调用点、路径候选和条件。“存在一条可能写入路径”不等于“A 每次必然写入”。多条路径可以归并展示，不能将路径拼成不存在的执行顺序。锁是访问上下文的属性，不能因为函数某次持锁就给整个函数或整个资源标“始终受保护”。

注册/注销是一类关系，注册表也可能有写入/清空效果；它们不自动等同初始化/释放。可辨识的静态描述表、运行时注册状态分别建模。外部自定义函数/库作为已知边界终点；不补画未知内部资源效果。

资源不局限于文件级全局变量，还包括具有共享范围的堆对象、成员容器、单例、内存、锁、寄存器及设备状态。接口也可能通过调用参数、消息、文件或外部服务交互；**当前资源图仅表达已建模的资源耦合，不能宣称没有连线就没有交互**。是否将消息/外部对象纳为资源，需要独立身份和来源，不能为了连通而造节点。

|---|---|---|---|

| READ-02 | 函数的模块、进程/线程/执行域属性；设备与外部边界 | 点关系查看跨主体交接性质；缺主体身份时保留 unknown | 时序、端到端 |

| READ-05 | 初始化/去初始化等效果线及注册/注销标记 | 点注册资源查定义、注册点、分派读点和清理路径 | 文字树、端到端 |
| READ-06 | 资源操作的路径条件摘要，不在此展开完整判断树 | 点条件进入对应入口和调用点，保留资源关注 | 端到端、文字树 |
| READ-07 | 字段/实例键、值的来源或去向与转换摘要 | 点效果追到实际赋值或消费位置；未知转换显示断点 | 端到端、文字树、文件 |
| READ-08 | 资源类型、实例范围、字段、所有者和生命周期操作 | 点实例选定关注范围，查看创建/访问/释放方及定义 | 资源详情、资源变更链 |
| READ-09 | 状态字段的更新与约束摘要 | 点变化查看前置条件、后置效果和其他修改路径；旧值未知则不写确定旧值 | 资源变更链、端到端 |
| READ-10 | 锁资源及访问关系上的上下文摘要；异步交接有类型标记 | 点保护关系看获取/释放点、锁身份/模式及未知；追踪投递到完成 | 资源变更链、时序 |
| READ-11 | 失败条件上的释放、撤销、恢复效果 | 点异常效果查看错误原因、清理顺序及留下的状态 | 端到端、文字树、资源变更链 |
| READ-12 | 基础接口折叠后保留关注资源效果；外部调用显示边界 | 点黑盒看契约和效果摘要，选择查看源码或内部子流程 | 函数详情、子流程、文件 |
| READ-13 | 资源/函数旁的简短解释与来源，不混入确定关系 | 打开函数 AI 归纳查看机制和推断；回源码核对 | AI 归纳、文字树、文件 |
| READ-14 | 来源、确定性、变体、覆盖和截断标识 | 点证据定位源码；改变版本/变体后核对关系变化或失效 | 全部六视图 |

### 4.4 跨视图选择与折叠

跳转传递当前工作区、源码/快照版本、变体、入口、函数及可用的调用点/路径、资源身份。目标视图高亮相同实体；有多个上下文时列出候选，不能默选第一条路径并伪装唯一。缺少对应细节时保留选择并说明缺口。

资源相关函数点击保持“定位、高亮、源码详情不自动弹出”；点击画布空白收起详情，拖动不误触关闭。资源关注可映射到资源变更链，其他流程灰淡而非删除必要上下文。函数定义唯一不限制文字树、端到端及变更链保留多次调用实例。

组在原图展开/折叠并可嵌套，表达上层职责；复杂函数的子流程属于单独下钻，通过面包屑定位。基础接口可连同内部组归为黑盒并可移出库；折叠不能隐藏本次关注的资源副作用。端到端保持竖向正交实线、判断菱形、异常颜色和一键规整。上述要求延续 CW-02..10，不新增源码写回或实际设备执行权限。

## 5. 案例核对方式与验收

### 5.1 通信 Demo：从资源看清接口耦合

以下来自 [bus.c](../demo/code-view/bus.c)，是源码阅读，不是本轮新增运行观测：

| 关注对象 | 接口与实际访问点 | 资源图应表达 | 下钻必须保留的内容 |
|---|---|---|---|
| `routes[channel]` | `reset`；`bus_register/stub_route/bus_unregister → store_route`；`bus_send → lookup_route/check_length` | 初始化、写入、清空与读取；字段 `lane/max_len`，实例键 `channel` | 登记参数校验、未登记/超限返回；解析不到别名时读取保持 may/unknown |
| `staged_lengths` | `reset`；`bus_send → dispatch_transfer → submit_buffered → stage_payload` | reset 清零；发送路径只有通过前置检查且走缓冲分支时写入，不是所有发送都写 | 分支 `length > DIRECT_LIMIT`、lane 来源、写后读取返回；初始化单独列出 |
| `transfer_lock` | `bus_send` 的 1/0 赋值 | 模拟状态标志，不标真实互斥锁 | 串行模拟注释、调用前后赋值；不证明多线程保护 |
| 门铃写边界 | `commit_transfer → encode_doorbell → write_doorbell → platform_write` | 编码/写入意图与外部接口边界；设备行为未知 | 编码表达式、返回传播、平台模拟与真实 MMIO 的区别 |

### 5.2 大型 C++ 仓库：状态容器与 RAII

使用已固定版本的 [UBS Engine 案例](case-studies/ubs-engine-reading-analysis.md)，检查单例/模板账本、对象实例键、注册分派、异步投递与 RAII 锁是否能用同一套问题分析。`Modify` 的复制后修改与 `Update` 的锁内更新应分别解释；资源/锁的具体类名只作为仓库数据，不进入核心规则。

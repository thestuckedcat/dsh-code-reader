# 04 代码工作台：仓库理解能力差距分析

编号：**CL-READ-AUDIT-01**；日期：2026-11-23；审查代码基线：`c73f52c`。依据[通用框架 CL-READ-01](repository-understanding-framework.md)逐项核对。本文交付分析与改进设计，**不包含插件功能修复**。

## 1. 结论、证据范围与状态口径

当前已有原生右侧栏、六视图、资源定义/字段展示、基础接口、组/子流程、AI 归纳接入、模拟台账与部分跨视图选择。问题不是缺少图的数量，而是**业务解释、入口汇总、调用上下文和底层证据之间尚未形成完整的阅读链条**。尤其需要防止将可能路径显示为必然效果、将一次持锁概括为函数始终受保护。

本轮依据：本地插件源码/设计、通信 Demo C 源码、已下载 UBS Engine 的固定版本源码和已有案例证据。未重新验收浏览器、Host、真实设备或性能；历史验收仅说明相应版本和范围。本轮源码检查不等同完整运行验证。

| 状态 | 本文含义 |
|---|---|
| 已支持 | 存在可定位的实现；涉及运行行为时仍注明本轮未重测 |
| 部分支持 | 已有部分数据或交互，但不能覆盖所需语义 |
| 缺失 | 指明的代码路径未提供该表达/处理，结论限定到该路径 |
| 尚未验证 | 现有材料不足，不能判断能力或准确率 |

改进层分为 **文案/解释、视图投影、底层分析能力**；一项可以跨层。P0 优先阻止误导并建立理解入口，P1 补齐语义与导航，P2 扩展可选执行能力。以下验收标准均为后续待实现/待验证，不是本轮通过记录。

## 3. 逐项差距、改进与验收标准

### GAP-01 业务主线未成为六视图共同入口

- **角度/应有表达：** READ-01；资源用途和接口职责能联系到业务目标与完成条件。
- **当前证据/状态：** 部分支持。[workspace.py 的 overview](../engine/code_learning/workspace.py#L1033)返回声明的仓库组件与 binding 端点；[分层阅读指导](../skills/learn-code-workspace/references/layered-reading.md)已有顺序；[createModel](../client/model.cjs#L201)按直接调用数选择默认入口，归纳缺失时保留占位。不能写成“完全没有概览能力”。
- **理解风险：** 新人看到函数很多的入口，仍不知道系统要完成什么任务；统计性资源介绍也不能解释其业务作用。
- **改进/优先级：** P0，文案/解释＋视图投影。复用已有概览，组织业务目标、术语、模块、代表流程和完成条件；资源及函数摘要链接到这条主线。AI 业务分组是可修订候选，附依据。
- **验收标准：** 不先知道函数名也能从任务找到入口、关键资源和完成边界；缺摘要可继续看事实，不回落到 Demo 文案。

### GAP-02 执行域默认值和静态时序角色可能误导

- **角度/应有表达：** READ-02/10；资源访问者的域、主体及交接有依据。
- **当前证据/状态：** 部分支持且存在默认值风险。[model.cjs:39](../client/model.cjs#L39)缺省 `domain='kernel'`；[资源链模型](../demo/code-view/resource-chains-model.js#L25)同样缺省 kernel；[STATIC_SEQUENCE](../client/document.cjs#L204)固定“调用方/接口或业务函数/库边界”三类生命线，箭头均从调用方出发。此结论针对静态降级路径，不否认 observed 数据路径。
- **理解风险：** 用户态服务被误读为内核流程；嵌套调用及线程/服务交接关系被压平。
- **改进/优先级：** P0，底层分析能力＋视图投影。未知域保持 unknown；主体、执行域与 library 边界分开。时序生命线按已知参与者及真实父调用/交接关系产生。
- **验收标准：** 缺域不涂内核色；用户态进程和线程池可区分；已知调用的发起方正确，未知参与者明确标未知。

### GAP-03 文件位置可读，流程职责尚未串联

- **角度/应有表达：** READ-03；资源定义、流程步骤、文件和主要函数相互可导航。
- **当前证据/状态：** 文件视图已支持，职责导航部分支持。[文件高亮实现](../demo/code-view/c-highlight.js)、[model.roles](../client/model.cjs#L40)和[资源定义展示](../demo/code-view/page.html#L1423)能展示源码与位置；roles 默认主要是 `file:line`，不是文件业务职责。
- **理解风险：** 用户知道“代码在哪里”，仍不知道“为什么分在这里，负责主线哪一步”。
- **改进/优先级：** P1，文案/解释＋视图投影。补流程排序的文件—主要函数—职责—关键对象导航，按编译目标/符号及实现归纳，目录名只作线索；不向纯文件视图塞满分析面板。
- **验收标准：** 从一个资源能找到定义文件、直接访问函数和该函数负责的流程阶段；职责推断能回到依据。

### GAP-04 参数与结果合同仍带执行样例限制

- **角度/应有表达：** READ-04；基础接口及入口能准确解释参数、输出、副作用与错误。
- **当前证据/状态：** 部分支持。[model.cjs](../client/model.cjs#L65)生成签名/返回/校验摘要，但[interfaceFields](../client/model.cjs#L139)均为 int32 数值范围；[静态场景表单](../client/document.cjs#L194)使用 number；[sim-worker](../lib/sim-worker.mjs#L157)将结果转 int32 并用负数判失败。对 UBS Engine 的正数错误码是静态反例，未实际运行该仓库。
- **理解风险：** 字符串、uint64、结构体/输出指针及结果约定被抹平；“无法模拟”容易被误读为“无法理解接口”。
- **改进/优先级：** P1，底层分析能力＋文案；通用执行扩展为 P2。阅读先保留原始类型、方向、所有权和结果合同；不能执行的类型显示原因，未知返回值保持原值/未知含义。
- **验收标准：** 能解释字符串、64 位大小、输出结构指针、枚举和正数错误码；没有执行 profile 仍能阅读契约。

### GAP-05 注册、资源生命周期与触发不能混为写入

- **角度/应有表达：** READ-05；表定义、注册写入、分派读取、绑定目标、触发和注销分别有证据。
- **当前证据/状态：** 部分支持。[resourceEffects](../client/model.cjs#L94)保留访问动作，[资源栏](../demo/code-view/page.html#L1490)有初始化/修改/释放/Read；前端函数邻接主要来自 [d.calls](../client/model.cjs#L53)，不能仅靠它恢复协议注册链。真实仓库自动绑定覆盖本轮尚未验证。
- **理解风险：** 将“写入了注册状态”解释为“handler 一定执行”；初始化、登记、撤销被合并。
- **改进/优先级：** P0，底层分析能力＋视图投影。保留注册/分派关系类型、作用域和匹配键；表资源操作与绑定关系同时展示，缺触发证据时留断点。
- **验收标准：** 同键不同模块不误连；能定位表定义、注册点、分派点、注销点；不将静态匹配标为 observed。

### GAP-06 路径汇总与重复调用丢失上下文

- **角度/应有表达：** READ-06/10；入口效果能追到每个必要调用点及路径条件。
- **当前证据/状态：** 部分支持，存在信息丢失。[model.cjs:60](../client/model.cjs#L60)按目标去重；[findPath](../client/model.cjs#L107)返回首条路径且深度上限 24，汇总时合并 via 集合；[resource-chains-model.js:23](../demo/code-view/resource-chains-model.js#L23)每入口按函数去重。后端明确[无调用点分支未建模](../engine/code_learning/five_views.py#L2042)。文字树仍有逐调用点 readingSteps，不能据此说所有视图均已去重。
- **理解风险：** 先后两次调用或不同条件调用被当作同一次；via 的集合顺序被误读成执行顺序；未展示分支被误认为不存在。
- **改进/优先级：** P0，底层分析能力＋视图投影。函数定义、调用点、路径上下文分别保留；资源图可以汇总，详情必须列路径候选和条件。CFG 缺口明确显示；循环/递归有界展开并允许引用，不静默删路。
- **验收标准：** 同一入口两次调用保留两个调用点；分支路径互不拼接；超过范围可见截断原因；无调用点的局部 return 不被当完整 CFG 已覆盖。

### GAP-07 资源访问事实未形成完整数据流解释

- **角度/应有表达：** READ-07；入口到字段的访问保留实际访问点、键和值来源、转换和条件。
- **当前证据/状态：** 部分支持。[resourceEffects](../client/model.cjs#L94)保留 function/access/expression/certainty/source；[入口关系投影](../client/model.cjs#L112)生成摘要和 via，但该前端效果结构没有独立的调用点、路径 guard、值来源/目标关联字段。
- **理解风险：** 把“字段被某内部函数访问”概括成“入口无条件写该字段”，无法解释参数如何变成资源状态。
- **改进/优先级：** P0，底层分析能力＋视图投影。直接访问与入口投影分层保留；语义数据流可用时关联参数、别名和转换。仅有表达式时展示表达式和未知，不由 UI 猜值。
- **验收标准：** `bus_send` 路径中的 `staged_lengths` 写入带缓冲分支及前置条件，reset 初始化另列；`lane` 来源可追到资源/参数或显示断点；may 读取不因入口汇总升级为 exact。

### GAP-08 共享资源不能仅靠文件级 static 扫描恢复

- **角度/应有表达：** READ-08；声明、类型、容器、实例键、字段及所有权可区分。
- **当前证据/状态：** 部分支持。语义资源来自 coupling；[scanSourceResources](../client/model.cjs#L236)只补简单文件级 static，以名称匹配函数内文本访问，不做词法作用域绑定。不能据此否定 Atlas 对其他资源的能力；但该补充路径会漏普通全局/局部静态单例，并有同名局部遮蔽误归属风险。
- **理解风险：** 同名不同实例被合并；局部副本修改被当作共享对象修改；容器发布动作与字段赋值混为一谈。
- **改进/优先级：** P0，底层分析能力。使用语义对象身份和别名/所有权证据；容器效果可通过版本化适配规则补充。词法候选不混成确定访问，无法绑定时保留候选和限制。
- **验收标准：** 普通全局、函数局部 static、同名遮蔽、堆共享对象及模板容器分别检查；不同类型/节点/键不误合并，不能解析的实例键保持符号表达。

### GAP-09 字段说明、状态转换与不变量需分层

- **角度/应有表达：** READ-09；资源有用途和字段说明，访问能联系到状态检查与变化。
- **当前证据/状态：** 部分支持。[resourcePresentation](../client/model.cjs#L83)缺说明时显示类型/访问统计，字段默认“作用待核实”；[字段详情](../demo/code-view/page.html#L1437)支持说明与来源。资源链可显示写入表达式，但不等于已提取完整状态转换。
- **理解风险：** 新人看到写点仍不知道业务含义；根据一次赋值猜出所有允许状态或确定旧值。
- **改进/优先级：** P1，文案/解释＋底层分析能力＋视图投影。分别保存字段含义、状态写点、路径条件和推断约束；未解析旧值时用 `state ← X`，不虚构 `Y → X`。
- **验收标准：** 状态写入可跳 guard/写点；用途说明有依据；不完整状态集和不变量推断有明确标记。

### GAP-10 锁保护属于调用上下文，异步标记不等于因果

- **角度/应有表达：** READ-10；资源访问关联锁身份、模式、获取/释放、调用点和完成上下文。
- **当前证据/状态：** 示例/轨迹标识部分支持，真实锁覆盖尚未验证。[锁示例](../demo/code-view/resource-chains-model.js#L34)明确未编译执行；[sourceData](../demo/code-view/resource-chains.js#L56)将 transfer_lock 标 simulated；真实快照锁未知的提示已存在。但同入口函数合并及按 entry/functions 匹配 lockSpan 不足以区分同入口的不同持锁调用。异步观测声明已有[独立合同](five-view-contract.md)，不代表静态 continuation 全覆盖。
- **理解风险：** 把模拟标志当互斥锁，或把持锁的一条路径扩展成所有路径；把投递返回当最终完成。
- **改进/优先级：** P0，底层分析能力＋视图投影。按访问实例分析锁、别名及 RAII 作用域；区分锁表管理锁、业务对象锁、容器内部锁。异步交接保留生产者、任务/回调及关联证据。
- **验收标准：** 同入口持锁/未持锁各调用一次同一函数时显示差异；RAII 提前返回标有依据的释放；未证明不持锁时显示 unknown，不标确定“无锁”；提交/接受/执行/最终完成分开。

### GAP-11 异常边需要关联实际清理与留下的状态

- **角度/应有表达：** READ-11；异常返回、资源释放/补偿及业务完成状态可相互定位。
- **当前证据/状态：** 部分支持。[readingSteps](../client/model.cjs#L63)收集源码 return/goto 等行；端到端有异常投影和部分 guard；无完整 CFG 时不能证明所有清理或析构路径。[bus.c](../demo/code-view/bus.c#L167)能直接核对调用后清标志再返回。
- **理解风险：** 红色返回线被当作完整错误解释；平台错误、调度失败、投递成功和业务完成混淆。
- **改进/优先级：** P1，底层分析能力＋视图投影。错误边关联受影响资源和清理步骤；区分已完成、已投递、部分提交、补偿失败和未知。不按返回值正负推断所有接口语义。
- **验收标准：** 失败前后的资源效果可追踪；缺清理证据显示缺口；RAII 和显式清理分别有来源，不凭红线推断已经释放。

### GAP-12 黑盒、组与子流程不能隐藏关注资源效果

- **角度/应有表达：** READ-12；稳定接口可以折叠，但契约、副作用、失败和实现简介可见。
- **当前证据/状态：** 交互已有，语义部分支持。[基础接口候选](../client/model.cjs#L211)在 decoupling=independent 时加入 basic；[文字树](../client/document.cjs#L162)以契约代替内部步骤；[子流程页签](../demo/code-view/page.html#L1273)按入口/基础接口调整可见性。真实候选独立性和全效果摘要尚待跨仓验证。
- **理解风险：** 因是基础接口而漏看锁、注册、副作用或错误转换；同一实现被外层及子流程重复展开。
- **改进/优先级：** P1，文案/解释＋视图投影＋底层效果摘要。区分组的原图抽象、子流程下钻和基础接口库；候选可复核/移出。折叠保留关注资源效果和缺失效果说明。
- **验收标准：** 公共函数实现唯一但调用上下文可多份；黑盒可读输入输出/校验/副作用；移出后恢复展开，资源关注不丢失。

### GAP-13 归纳内容需要联系主线与证据

- **角度/应有表达：** READ-13；不超过 500 字说明函数在主线中的作用、关键机制和必要取舍。

# 04 交互式 C 代码视图初稿

`CL-VIEW-D1` · 2026-11-12 · 供评审。依据 [CL-VIEW-P0](interactive-code-view.md)。原型验证「从一次下发回到 C 实现」的阅读方式。

2026-11-14 画布修订。默认使用可平移、缩放和拖动节点的流程图，入口、模拟设备出口与调用方返回各自有边界块。补充 C 样例的短包直发（≤48 B）与长包暂存分支，两条路径共享编码与寄存器写入。先扩展原有 C/Wasm 测试，再沿用已有源码范围和轨迹事件绘制画布，最后检查拖动、连线、边界与分支切换。画布布局和连线为这个样例配置，运行状态来自同一份 C 的观测事件。

### 流程组与函数子流程

- `CL-VIEW-04` 流程组归纳一个业务阶段，可包含函数或其他组。折叠为一个节点，跨组连线接到组端点；展开后在原画布显示成员，仍可单独折叠子组。样例成员关系由场景配置提供，标题与描述由成员职责归纳生成。场景后续可提供自由编组、改名和持久化。
- `CL-VIEW-05` 函数详情在「源码／子流程图」之间切换。子流程按 AST 的直接调用展示一层，基础函数和库调用保留为叶子；点下一层可沿同一调用路径继续。请求链路标题下用面包屑显示「主流程 → 业务组 → 当前调用路径」。共享函数使用同一源码身份，路径保留各自调用者。清点一次运行的观测时使用实际经过的调用入口。
- 请求失败汇到一个错误出口，具体原因和返回码放在边上与本次结果中。点击画布空白关闭源码查看，拖动仍可保留查看状态。样例前置注册与结构体／寄存器读数收进「样例输入与观测」，主画布承载边界、函数、组和关系。

修订顺序为先核折叠投影与共享调用的行为，再接入画布和详情，最后用合成样例在浏览器测试。首个验收是展开「传输准备」，再展开暂存子组，沿 `submit_buffered → commit_transfer` 进入子流程后可从面包屑直接回到原主图。

### 接口、资源与多仓边界

本轮按「C 样例与证据 → 场景记录和接口库 → 画布与详情 → 浏览器验收」实现。复用已有 Clang AST、WebAssembly 和组投影，引入独立的平台库 C 单元，连接样例 `driver` 和 `platform` 的定义与调用。最小验收为注册路由后下发成功，回退该次下发和注册后再下发得到未注册；对平台写入返回值打桩后，观察失败分支及写入状态。

- `CL-VIEW-06` 基础接口归类依据接口契约、局部状态及外部依赖。原型自动收录有明确参数契约、仅依赖自身参数和已识别辅助函数、没有全局资源访问的接口；可手动收录或移出。进入基础接口先看入参、出参、功能、实现摘要和校验。调用传递出的副作用须反映在摘要，归类不能改变实际执行。
- `CL-VIEW-07` 模拟区可调用登记接口、发送入口和独立中断入口，保存入参、返回码、C 事件及对资源的影响。平台库调用可注入返回码，真实入口由用户调用。回退删除最近 N 条操作，从初始状态重放保留前缀，以保持接口之间的依赖一致。仅适用于确定性的本地样例。
- `CL-VIEW-08` 资源列表包含文件静态表、全局/静态可变状态及模拟设备资源。按当前函数高亮并置顶，初始化、修改、释放按已知证据链接到函数。函数详情资源页标出受保护的调用上下文、资源操作和临界字段。样例锁和 IRQ 为教学用模拟机制。
- `CL-VIEW-09` 主图支持按函数名查找并定位、规整布局、异常边上色，以及独立的 IRQ 方块。函数子流程继续使用面包屑查看跨单元调用。移除并列调用树入口。
- `CL-VIEW-10` 04 已有多仓 workspace 登记、源码查询和跨仓 ABI 候选。产品视图应以 `repo + revision/variant + symbol` 锚定函数和资源，并以各接口为组接起共享状态与候选绑定。原型演示两个逻辑仓的 C 源码与明确的静态链接。实际多仓导入、构建与间接绑定仍待接入现有 04 工具。

- `CL-VIEW-11` 区分用户态与内核态，右上角 `?` 查看全部特殊颜色。样例标注的是角色，执行仍在单个 Wasm 环境。全局资源展开后显示作用、Clang 定位的定义源码和初始化、修改、释放、Read 四类关联。关联函数只定位画布，主链外函数显示为无连线的参考节点。函数详情另有离线预生成的 AI 归纳，依据样例源码，最多 500 字。本轮验收先核对静态表源码与读取者，再验证定位、图例和归纳页签。

- `CL-VIEW-12` 顶部可在「请求链路」与只读「文件视图」间切换。文件视图左侧按源码归属显示文件树，右侧带行号显示同一构建包中的完整源码。切换期间保留文件选择、文件夹展开、画布与模拟执行记录。

- `CL-VIEW-13` 请求链路按接口提供单一流程图，默认打开 `bus_send()`。平级入口导航切换到注册、注销或模拟 IRQ。图中分组属于当前入口；入口函数详情通过「返回入口流程」回到同一图。非入口函数仍可按直接调用下钻，面包屑回到所属入口。复用既有画布和样例 C/Wasm 日志，先验收入口隔离、分支高亮和返回原图，再核对资源定位。各入口图的结构来自对应样例源码，由 Demo 配置表达。

- `CL-VIEW-14` 新增资源关系图、可折叠文字树与单入口端到端图的切换。先在样例 C 中核对入口、资源字段、外部终点和分支顺序，再用同一个入口与调用路径同步高亮。资源图以单个资源连接参与接口，标记读写方向、字段、初始化与清理。外部函数在调用方的域结束，模拟 IRQ 保留独立触发入口。文字树按源码分支和调用点提供下钻与源码。端到端图复用已有画布和运行轨迹，一个入口对应一张图。验收从 `routes[channel]` 看登记到发送的状态依赖，再从 `lookup_route()` 在三个视图间往返。Demo 的关系和分支文本取自合成源码，用显式配置表达；真实仓库仍需关系提取与证据核验。

- `CL-VIEW-15` 资源关系图和端到端图共用画布交互，资源、接口及外部终点都可手动移动，连线跟随节点。点击全局资源打开定义面板，显示声明和静态初始化、可用的结构体定义、源码位置与读写关系。定义从本地 Clang 源码范围取得，侧栏全局资源使用同一段源码预览。

- `CL-VIEW-16` 资源图改为三列，每个入口或外部终点函数只占一个节点，每个全局资源只占中间的一个节点。读写兼有时共用函数节点，箭头用方向、颜色和动作短注释标记关系。默认列位置仅用于布局。内部辅助函数和字段证据继续从资源详情进入。验收先核对登记和发送对同一 `routes` 节点的读写关系，再检查两侧函数、连线随拖动更新及资源定义面板。

- `CL-VIEW-17` 资源节点分别配色并显示用途简介，连线沿用访问关系配色。资源详情把 Clang 提取的结构字段与基于样例读写位置的注释配对。模拟门铃另外解释源码中显式编码的位段。字段用途为依据样例源码的解释，保留原始定义供核对。

- `CL-VIEW-18` 端到端画布沿用拖放与缩放，使用基础流程图的端点、处理、判断和输入输出符号。判断边标注条件，折叠组投影为一个处理框并保留跨组连线。按节点坐标绘制，不裁切到预设纸张范围。形状参考 [Visio 基础流程图](https://support.microsoft.com/en-us/visio/create-a-basic-flowchart-in-visio)。
- `CL-VIEW-19` 时序图接受可重复的有序接口和逐步参数。先构造独立样例实例，再按选择执行并用 C 事件绘制调用、资源访问、平台写入与返回。时间轴表示事件顺序。首次验收用相同通道比较「登记 → 发送」和反向执行；后者应出现查表失败，且无该次设备写入。模拟 IRQ 只在选择该接口后出现。

## 一次使用

1. 在「打桩模拟」选择 `bus_register()` 读取 C 静态默认表并登记路由，或执行 `stub_route()` 直接注入 `lane` 和 `max_len`。初始表为空。
2. 执行 `bus_send()`。展开执行记录查看实参、返回码和 C 事件。可为 `platform_write()` 设置返回并重试，也可回退末尾 N 条后观察之前的状态。从发送流程进库函数时，源码文件与资源归属显示为 `platform`。
3. 在执行图展开接口组，按函数名搜索。点击节点查看源码、资源或基础接口契约。在「全局资源」查看静态表内容和资源的初始化、修改或清除入口。
4. 查看代码时可打开同一份 C 文件。若要验证实现修改，可编辑样例源码、重新生成页面，再提交相同参数比较结果。图内编辑和连接目标驱动属于后续产品选择。

## 实现路线与来源

先做固定 C fixture 与行为测试，再生成可离线打开的单文件界面，最后用真实浏览器检查交互。首个验收是默认请求 `channel_id=1, length=48` 经接口注册命中 `lane=2, max_len=64`，模拟地址 `0x1040` 写入 `0x00020030`；改成通道 0 后看到查表未命中和空的写入记录。

| 来源 | 采用方式 |
|---|---|
| 04 `d884bd4` 的源码、关系与可信度设计，及 §8.1 分层阅读 | 借鉴文件/行号定位、静态候选与执行结果的区分、函数折叠和状态交接。样例独立于插件运行时。 |
| 本机 Clang/LLD 16.0.4 | 调用现有编译器，AST 提取样例的直接调用与函数范围。同一 C 文件编译为 wasm32，由浏览器执行。 |
| 合成 `bus.c` | 自行实现一个注册表、查表、长度校验和模拟寄存器写入。由 C 显式发送事件和行号。 |

原型只读取固定样例，构建只执行固定编译命令。浏览器内的运行时表和寄存器槽按次重置。产品要接真实仓库时，需要固定源码版本与构建变体，单独定义注入点、执行环境和证据收集方式。

## 验收与后续取舍

| 场景 | 通过标准 |
|---|---|
| 默认接口注册 | 看到静态表 `route_defaults` 的配置变成 `routes[1]`，请求命中后产生模拟写入。 |
| 打桩换一条路由 | `lane=3, max_len=96` 时同一请求写入 `0x00030030`，轨迹显示直接注入。 |
| 未注册或超长 | 区分查表未命中和长度超限，均保留真实返回码，清空上次写入。 |
| 参数无效 | 长度 0 进入驱动，点亮参数无效出口，返回 `-22`。 |
| 分支与深层调用 | 48 B 走直发，49 B 将长度写入暂存槽后继续；两条路径汇入提交、编码和寄存器写入。 |
| 画布和边界 | 拖空白移动视野，拖一个节点可见相邻连线重绘。缩放和重置后仍能定位入口、错误返回、调用方返回与模拟设备出口。 |
| 查看函数实现 | 从主图下钻到函数子流程，可从面包屑返回。函数详情能核对源行、观测值和资源证据。 |
| 平台边界打桩 | 设置失败返回后再发送，失败码沿调用链传回，异常边点亮，模拟寄存器没有写入。 |
| 接口级回退 | 删除最近 N 条操作后，重放保留的调用，重新得到对应表项、寄存器与中断计数。 |

待选择的高层边界为真实设备下发和图内源码写回。真实设备接入需要界定哪些写入可观测、哪些值要读回。写回体验需要差异预览与变更后的证据刷新。初稿采用独立本地页面作为体验载体。

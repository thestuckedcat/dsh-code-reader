## 已有确认与可见成品

当前产品依用户后续明确要求，以 **DSH plugin + 原生右侧代码工作台** 交付，配套 skill 提供使用/生成指导。下表保留早期“skill＋本地报告、面板后置”的历史确认；界面形态以 CL-PF-08/09 与 CL-UI-R1 的后续修订为准。已明确的选择不再逐按钮确认。

| 稳定ID | 产品范围与用户得到的结果 | 决定依据 |
|---|---|---|
| CL-PF-01 | 在Harness对话中启动学习skill，登记一个研发workspace中的单个或多个仓库，选择目标构建变体 | 用户明确单仓/多仓、Linux驱动及用户态；仓库登记与变体选择是设计决定 |
| CL-PF-02 | 先看组件职责、仓库边界及关键接口的小地图，再围绕一个API、行为或问题沿源码展开 | 用户“快速理清代码关系、专门学习代码”；具体问题驱动旅程是设计决定 |
| CL-PF-03 | 同时解释调用、数据、对象生命周期、错误及同步关系；跨用户态/UAPI/内核边界保留证据和不确定性 | 用户领域与VSCODE_READER要求；静态分析不能证明真实运行是硬边界 |
| CL-PF-04 | 得到可回到源码的解释、本地导航/离线报告、未解决问题和版本化学习记录；可暂停续读、导出Markdown/JSON | Q04已确认skill＋本地证据导航/报告；记录及导出细节是设计决定 |
| CL-PF-05 | 普通提问直接解答；明确学习复盘时区分预测、实际观察和待验证，最多给一个具体下一步 | 用户行为守则；不替用户声称已理解/已验证 |
| CL-PF-06 | 首版不要求专用Harness学习面板，不重写Atlas解析器，不把Kbuild迁为CMake | 面板后置已确认；复用与构建适配为设计决定 |

`CL-PF-02/03` 局部补充（已实现）：单函数问答先定位它在业务总框架中的位置，再给出涉及文件和主要函数、关键结构体、软表与硬件资源的读写、边界入口与出口；业务图与局部图分开、通过入口/Selection 关联。落地为 skill 参考 [分层阅读与函数定位](../skills/learn-code-workspace/references/layered-reading.md) + 合同测试（`engine/tests/test_skill_contract.py`，331 Python tests），设计见[分层阅读与函数定位](software-design.md#81-驱动代码分层阅读与函数定位)。

`CL-PF-07`（2026-11-12 用户提出，已交付插件版）：以 C 源码为底座的[交互式代码视图](interactive-code-view.md)，支持受控模拟下的参数与注册状态执行、分支和数据流下钻、调用图节点折叠及展开；五视图与 DSH 插件接入见[详细设计 CL-VIEW-D2](interactive-code-view-software-design.md)，分阶段验收见 `evidence/final-acceptance/`。真实设备下发和图内源码写回仍待产品确认（当前 gap）。

## 一次完整使用

`CL-PF-10`（2026-11-21 用户明确方向，设计记录、待实现）：新增“资源变更链”视角，多选全局/共享资源，把当前索引中所有相关调用链汇入同一画布。选中资源及字段/状态变化为前景，其他过程灰淡并略透明；原资源关系图同步关注集。锁保护属于具体调用上下文，模拟标志与未知范围不升级为真实互斥。“资源变更链”名称、约 0.7 背景透明度与按入口分组是可修改默认值。详见[CL-RES-01 设计](interactive-code-view-software-design.md#11-资源变更链与共享状态关注cl-res-01)。

`CL-PF-09`（2026-11-19 用户明确要求，已实现并隔离验收）工作台默认停靠于 DSH 对话右侧，支持关闭、恢复、调宽及宿主放大。内部直接复用当前 Demo 的五视图与交互。原生停靠与具体操作通过 49 项检查，范围与真实 CFG 等限制见 [CL-UI-R1 的 U01–U09](ui-demo-alignment.md)。原阶段记录保留各自范围，用户桌面热更新尚未验证。

例如提出“用户库提交任务后，驱动如何排队并完成通知”：选择已登记的用户库、共享UAPI、驱动仓库及对应CONFIG/版本 → 看到组件地图与入口候选 → 沿一条路径阅读带行号、文件摘要和构建条件的解释 → 分清编译器解析事实、间接调用候选和未知边界 → 保存本次学习及待验证问题。下次继续时先核源码/构建输入变化，再接着阅读；旧证据不能直接冒充当前事实。

无有效编译数据库、生成头或可信Linux分析环境时，显示限制，进入源码解释或已核快照学习模式。不会偷偷执行仓库构建脚本、联网拉依赖或用模型猜出完整关系。真实运行/硬件行为需另有观察证据；本轮没有执行用户仓库分析或测试。

## 载体与本地边界

skill负责阅读顺序、讲解、提问和停止；固定Atlas CLI负责已有结构/语义/快照；本地薄适配负责范围、执行隔离、证据与记录。索引、源码证据、报告和记录存本地；模型只使用已批准Provider，CLI不新增模型接收方。08可在以后打开报告，05只在明确用途与许可下接收学习经验，两者均不是04独立交付前提。

详细模块、schema、CLI、状态机、迁移、故障与验收见[软件设计](software-design.md)。本产品说明不宣称Atlas已适配真实业务内核，也不代表插件安装或运行验证完成。后续局部新增/微调按[修订规则](../../docs/design-change-policy.md)，只重核真正改变产品范围的选择。
